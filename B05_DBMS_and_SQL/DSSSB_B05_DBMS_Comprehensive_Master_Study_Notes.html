ANSI/SPARC 3-Schema Architecture Levels

1. External Level (View Schema)

Individual tailored views visible to specific user groups. Hides irrelevant or sensitive data (e.g., student sees grades, accountant sees fee balance).

2. Conceptual Level (Logical Schema)

The complete community view of the entire database. Describes all entities, attributes, relationships, and constraints independent of physical storage.

3. Internal Level (Physical Schema)

Describes physical storage structures: data blocks, file organizations, B+ tree indexes, hashing schemes, compression, and access paths on disk.

Logical Data Independence

The capacity to alter the Conceptual Schema (adding a table, adding a column) without requiring changes to External Schemas or existing application programs.

Physical Data Independence

The capacity to modify the Internal Schema (reorganizing files, rebuilding indexes, moving to SSD) without needing to alter the Conceptual or External schemas.

Concurrency Control Anomalies

• Dirty Read (W-R): Reading uncommitted data that later aborts.
• Unrepeatable Read (R-W): Re-reading a row gets modified data.
• Lost Update (W-W): Two transactions overwrite each other.
• Phantom Read: Re-querying finds new inserted rows satisfying condition.

Two-Phase Locking (2PL) Protocol
• Phase 1 (Growing Phase): Transaction can acquire locks, but CANNOT release any lock.
• Lock Point: Moment when the transaction holds all required locks.
• Phase 2 (Shrinking Phase): Transaction can release locks, but CANNOT acquire any new lock.
• 2PL guarantees Conflict Serializability, but can suffer from Deadlocks!
• Strict 2PL: All Exclusive (X) locks held until COMMIT/ABORT -> Prevents cascading aborts.

Indexing, Clustered vs Secondary Indexes & B/B+ Trees

Dense vs Sparse indexes, Clustered index storage, and B+ tree node capacity derivations.

B-Tree vs B+ Tree Architecture

• B-Tree: Keys and data record pointers stored in ALL nodes (both internal and leaves). Lower fan-out, deeper tree.
• B+ Tree: Data records/pointers stored strictly in Leaf nodes! Internal nodes store only search routing keys. All leaf nodes are linked in a doubly linked list, enabling rapid sequential range scans.

Clustered vs Secondary Indexes

• Clustered Index: Physical order of rows on disk matches index order (in InnoDB, primary key). A table can have at most ONE clustered index.
• Secondary Index: Created on non-ordered attribute; leaf nodes point to primary key or physical RID. A table can have multiple secondary indexes.
