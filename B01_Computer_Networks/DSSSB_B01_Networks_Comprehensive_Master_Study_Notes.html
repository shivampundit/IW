1.1 Physical vs Logical Topologies — Mesh, Star, Bus, Ring & Hybrid Metrics

  • Governing Mathematical Formula / Rule / Syntax: Full Mesh Links L = n(n − 1) / 2 (Duplex) • I/O Ports per node = (n − 1) • Total I/O Ports = n(n − 1)
  • Core Architecture & Technical Mechanism: In a Full Mesh topology of n nodes, every node has a dedicated point-to-point link to every other node, yielding maximum fault tolerance and privacy at the cost of O(n²) cabling. Star topology uses n links connected to a central Hub (Layer 1 broadcast) or Switch (Layer 2 unicast MAC learning); failure of the central device brings down the entire network (Single Point of Failure). Bus topology uses 1 backbone cable with n drop lines, n taps, and 2 50-ohm terminators (to prevent signal reflection/standing waves). Ring topology uses n links with unidirectional token passing (IEEE 802.5 / FDDI dual ring).
    • Exam-Style Worked Application & Verification: Worked Numerical: For a network of n = 12 computers in a Full Mesh topology, required duplex cables = 12 × 11 / 2 = 66 cables; I/O ports per computer = 12 − 1 = 11 ports; total I/O ports across the network = 12 × 11 = 132 ports.
    • 🎯 High-Yield DSSSB / KVS / GATE Exam Trap & Hinglish Memory Hook: Hinglish Tip: n nodes ke Full Mesh me Simplex links = n(n−1) hote hain aur Half/Full-Duplex links = n(n−1)/2 hote hain! Star, Ring aur Tree me links = n (ya n−1 for Tree) hote hain.

1.2 Transmission Modes (Simplex, Half-Duplex, Full-Duplex) & Switching Paradigms

  • Governing Mathematical Formula / Rule / Syntax: Packet Total Delay T_total = T_trans (L/R) + T_prop (d/v) + T_queue + T_proc • Bandwidth-Delay Product = BW × RTT
  • Core Architecture & Technical Mechanism: Simplex is unidirectional (Keyboard/Monitor, TV broadcast); Half-Duplex alternates direction sharing one channel (Walkie-Talkie, CSMA/CD Hub); Full-Duplex transmits simultaneously in both directions (Telephone, Switched Gigabit Ethernet). Hindi Tip / सरल व्याख्या: Peer-to-Peer vs Client-Server Architecture

Peer-to-Peer (P2P): Sabhi computers ka rank barabar hota hai (koi central master ya dedicated server nahi hota). Har node ek hi samay me client bhi ho sakta hai aur server bhi (e.g. BitTorrent, small home LAN). Isme setup sasta hai par security weak hoti hai.
Client-Server: Ek ya adhik centralized dedicated servers hote hain jo resources (files, database, print) manage karte hain, aur baki workstations (clients) request bhejte hain. Isme centralized security aur backup aasan hota hai.

1.2 Network Topologies: Comparative Deep Dive

1. Bus Topology

Multipoint

Sabhi devices ek common central cable (Backbone) se jude hote hain. Dono ends par Terminators lagaye jate hain jo signal reflection ko rokte hain.

Exam Trap: Agar backbone cable break ho jaye to pura network down ho jata hai. Cable cost minimum hoti hai.

2. Star Topology

Most Popular

Sabhi nodes ek central device (Hub ya Switch) se point-to-point dedicated link ke through jude hote hain.

Key Advantage: Kisi ek node ka wire cut hone se pura network affect nahi hota. Lekin central Hub/Switch fail hone se complete network crash ho jata hai (Single Point of Failure).

3. Ring Topology

Token Passing

Har device apne do padosi devices se circular loop me judta hai. Data flow unidirectional ya bidirectional ho sakta hai.

Protocol: Token Ring (IEEE 802.5) use karta hai. Data collision zero hota hai kyunki data send karne ke liye 'Token' zaroori hota hai.

4. Mesh Topology

Formula Must

Har node har dusre node se dedicated direct physical link se juda hota hai (Fully Connected Mesh).

Links required: L = n(n-1) / 2
Ports per device: n - 1
Highest reliability, zero traffic congestion, but highest cable cost.

5. Tree Topology

Hierarchical

Star aur Bus topology ka combination hota hai. Root node se branch out hokar secondary hubs judte hain.

Use Case: Corporate offices me department-wise network structuring ke liye best hai.

6. Hybrid Topology

Practical

Do ya do se adhik alag-alag topologies ko jodkar banaya gaya network (e.g., Star-Ring, Star-Bus).

Benefit: Highly scalable and flexible, par troubleshooting complex hoti hai.

DSSSB Numerical Trap: Mesh Topology Calculation

Question: Ek network me 12 computers ko fully connected Mesh Topology me jodna hai. Kitne physical links aur har computer par kitne I/O ports ki zaroorat hogi?

Nodes (n) = 12
Total Dedicated Links = n * (n - 1) / 2 = 12 * 11 / 2 = 66 physical links
Ports required per device = n - 1 = 12 - 1 = 11 ports
Total ports in the entire system = n * (n - 1) = 12 * 11 = 132 ports

2.1 Directional Transmission Modes

Simplex Mode
Unidirectional (sirf ek disha me data pravah). Receiver kabhi reply nahi bhej sakta.
Udaharan: Keyboard to CPU, Traditional TV broadcast, Radio.
Half-Duplex Mode
Dono dishaon me data ja sakta hai, lekin ek samay me keval ek hi disha me.
Udaharan: Walkie-Talkie ("Over and Out"), traditional Ethernet Hub.
Full-Duplex Mode
Dono dishaon me ek sath (simultaneously) data send aur receive ho sakta hai.
Udaharan: Mobile phone conversation, Modern Switched Ethernet.

• Hub: 1 Collision Domain, 1 Broadcast Domain (Dono me se kisi ko nahi todta).

Chapter 4

OSI 7-Layer & TCP/IP Model: Functions & PDU Mapping

Core Conceptual Pillar

ISO dwara 1984 me Open Systems Interconnection (OSI) reference model diya gaya tha. Isme 7 layers hoti hain (Bottom to Top mnemonic: Please Do Not Throw Sausage Pizza Away → Physical, Data Link, Network, Transport, Session, Presentation, Application).

Layer 7: Application Layer PDU: Data / Message

User interface aur network services provide karta hai. E-mail, file transfer, web browsing.

Protocols: HTTP, HTTPS, FTP, SMTP, POP3, IMAP, DNS, DHCP, Telnet, SSH, SNMP.
Layer 6: Presentation Layer (Syntax & Semantics) PDU: Data / Formatted

3 Mukhya Kaam: 1. Translation (EBCDIC to ASCII), 2. Encryption & Decryption (Security), 3. Compression & Decompression (Space saving).

Formats: JPEG, MPEG, GIF, SSL/TLS handshake translation.
Layer 5: Session Layer PDU: Data / Session Token

Dialog control (Simplex, Half-duplex, Full-duplex) establish, maintain aur synchronize karta hai. Checkpoints aur synchronization points insert karta hai taaki network crash hone par poori file shuru se download na karni pade.

Protocols: NetBIOS, PPTP, RPC, Sockets session management.
Layer 4: Transport Layer (Heart of OSI) PDU: Segments (TCP) / Datagrams (UDP)

End-to-End Delivery: Source process se destination process tak message deliver karta hai using Port Address (16-bit). Segmentation aur reassembly, Flow control (sliding window), Error control (checksum, ARQ), aur Connection management.

Protocols: TCP (Connection-oriented, Reliable), UDP (Connectionless, Unreliable).
Layer 3: Network Layer (Host-to-Host Delivery) PDU: Packets

Source host se destination host tak packet routing karta hai using Logical IP Address (32-bit IPv4 / 128-bit IPv6). Routing algorithms (Dijkstra, Bellman-Ford) aur packet fragmentation.

Protocols: IPv4, IPv6, ICMP (Ping, error reporting), IGMP (Multicasting), ARP (IP to MAC), RARP, Routing protocols (RIP, OSPF, BGP).
Layer 2: Data Link Layer (Hop-to-Hop / Node-to-Node Delivery) PDU: Frames

Bits ko frames me pack karta hai. Physical addressing using 48-bit MAC Address. Framing (bit/byte stuffing), Error detection (CRC, Parity, Checksum), Flow control (Stop & Wait, GBN, SR), aur Media Access Control (CSMA/CD in Ethernet, CSMA/CA in Wi-Fi).

Divided into 2 Sublayers: LLC (Logical Link Control - 802.2) and MAC (Media Access Control - 802.3).
Layer 1: Physical Layer PDU: Raw Bits (0s and 1s)

Physical medium ke upar raw bits ko electrical, optical, ya radio signals ke roop me transmit karta hai. Pin layout, voltage levels, data rate (bps), bit synchronization, physical topologies.

Hardware: Cables, Connectors (RJ-45), Repeaters, Hubs, Modems.

FORMULA & STEP-BY-STEP Subnetting Master Shortcut for DSSSB Exams

Kyun karte hain Subnetting? Ek bade network ko chhote logical sub-networks (subnets) me divide karne ke liye, taaki IP wastage ruke aur broadcast traffic control ho sake.

1. Subnets Count Formula:
Number of Subnets = 2^s
(jahan s = HostID se borrow kiye gaye subnet bits)
2. Usable Hosts per Subnet:
Usable Hosts = 2^h - 2
(jahan h = bache hue remaining host bits; -2 kyunki First = Network ID, Last = Broadcast ID)
Real Exam Numerical: /27 CIDR Subnetting
Given IP Block: 192.168.10.0/27
• CIDR prefix = 27 (27 ones, followed by 5 zeros)
• Subnet Mask = 11111111.11111111.11111111.11100000 = 255.255.255.224
• Borrowed bits (s) from Class C (default /24) = 27 - 24 = 3 bits
• Number of Subnets = 2^3 = 8 Subnets
• Remaining host bits (h) = 32 - 27 = 5 bits
• Usable hosts per subnet = 2^5 - 2 = 32 - 2 = 30 hosts per subnet
• Block Size (Magic Number) = 256 - 224 = 32
Subnet 1: Net ID = 192.168.10.0, Usable Hosts = .1 to .30, Broadcast ID = 192.168.10.31
Subnet 2: Net ID = 192.168.10.32, Usable Hosts = .33 to .62, Broadcast ID = 192.168.10.63

IPv6 Essentials (128 Bits)

Structure & Representation
• 128 bits long (16 bytes), written as 8 groups of 4 hexadecimal digits separated by colons (2001:0db8:85a3:0000:0000:8a2e:0370:7334).
• Leading zeros can be omitted (:0000: → :0:).
• Consecutive all-zero blocks can be compressed once using double colon (::).
IPv6 Features vs IPv4
• No Broadcast: IPv6 uses Unicast, Anycast, and Multicast (Broadcast eliminate ho chuka hai).
• Fixed 40-byte base header (faster router processing).
• Built-in mandatory support for IPSec (Security).
• Loopback address: ::1 (equivalent to 127.0.0.1).

6.1 TCP vs UDP: Complete Comparative Matrix

Feature TCP (Transmission Control Protocol) UDP (User Datagram Protocol)
Connection Type Connection-Oriented (requires 3-way handshake before data transfer) Connectionless (Fire-and-forget, data sent immediately)
Reliability Guaranteed delivery using Acknowledgment (ACK) & Retransmission. Unreliable (Best Effort Delivery). Packet loss may happen.
Ordering of Packets Preserved. Sequence numbers ensure packets reassembled in exact order. No ordering guaranteed. Application must handle sequencing.
Header Size 20 to 60 bytes (Variable, default 20 bytes) 8 bytes fixed (Source Port, Dest Port, Length, Checksum)
Speed / Overhead Slower due to heavy header, ACK processing and congestion control. Very Fast with low latency and minimal overhead.
Flow & Congestion Control Yes, Sliding Window flow control + Slow Start congestion control. No flow control, no congestion control.
Communication Mode Strictly Unicast (One-to-One). Unicast, Multicast, and Broadcast supported.
Real-world Examples HTTP/HTTPS (Web), FTP (File transfer), SMTP (Email), SSH. DNS queries, DHCP, VoIP, Online Gaming, Video Streaming (RTP).

TCP 3-Way Handshake (Connection Establishment)

Step 1: Client → Server [SYN]
Client sends SYN flag with initial sequence number Seq = x. Client enters SYN-SENT state.
Step 2: Server → Client [SYN + ACK]
Server acknowledges with Ack = x + 1 and sends its own Seq = y. Server enters SYN-RECEIVED state.
Step 3: Client → Server [ACK]
Client sends final Ack = y + 1. Both enter ESTABLISHED state and data transfer begins.
Connection Teardown: 4-Way Handshake using FIN and ACK flags.

Sliding Window Protocols: Exam Formulas

1. Stop-and-Wait ARQ
Sender Window = 1, Receiver Window = 1. Sequence numbers needed = 2 (0 and 1, 1 bit).
Efficiency η = 1 / (1 + 2a), where a = Tp / Tt
2. Go-Back-N (GBN) ARQ
Sender Window = N, Receiver Window = 1. Out-of-order frames discarded. Cumulative ACK used.
Min Sequence Numbers = N + 1 (using k bits, N ≤ 2^k - 1)
3. Selective Repeat (SR) ARQ
Sender Window = N, Receiver Window = N. Sirf damaged frame retransmit hota hai. Independent ACK.
Max Window Size = 2^(k - 1) = 2^k / 2

Feature Symmetric Key Cryptography (Secret Key) Asymmetric Key Cryptography (Public Key)
Number of Keys Single shared key (Same key for encryption & decryption) Key Pair (Public Key for encryption, Private Key for decryption)
Key Distribution Big problem! Secret key must be exchanged over secure channel. Easy. Public key can be openly published anywhere.
Computational Speed Extremely Fast (Suitable for bulk data encryption) Slow (100–1000x slower due to complex prime number math)
Number of Keys for N users N * (N - 1) / 2 keys 2 * N keys (1 Public + 1 Private per person)

8.3 Malware & Threat Taxonomy

Computer Virus
Needs a host program/file to attach to. Human action (file execution) is required to replicate and spread. First PC virus: Brain (1986).
Worm
Self-replicating! Does NOT need a host program or human execution. Propagates independently across networks, consuming bandwidth. First worm: Morris Worm (1988).
Trojan Horse
Appears to be useful or harmless software (e.g. game, utility) but hidden inside is malicious code that creates a backdoor. Does NOT self-replicate.
Ransomware
Victim ki files ko strong encryption se lock kar deta hai aur decrypt karne ke liye Bitcoin/cryptocurrency me ransom (phirauti) mangta hai (e.g. WannaCry, Petya).
Phishing
Social engineering attack jisme fake legitimate-looking emails ya websites ke through user ke passwords, credit card credentials churaye jate hain.
Firewall Types
Packet Filter: L3/L4 inspection based on IP/Port. Stateful Inspection: Tracks active TCP connection state. Application Proxy: L7 deep packet content inspection.
