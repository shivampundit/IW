Process Control Block (PCB) Contents

• PID: Unique numeric Process Identifier.
• Process State: New, Ready, Running, Waiting (Blocked), Terminated.
• Program Counter (PC): Address of next instruction to execute.
• CPU Registers: Accumulator, index registers, stack pointer.
• Memory Management Info: Page tables or segment tables.
• Accounting Info: CPU time used, time limits.
• I/O Status: List of open files and allocated devices.

Threads vs Processes Matrix

• Process: Heavyweight unit with isolated address space. Context switch is slow (flushes TLB, reloads page tables).
• Thread (Lightweight Process): Exists within a process. Shares code section, data section, heap, and open files with peer threads.
• Private to each Thread: Program Counter (PC), Register set, and private Call Stack.
• Context switch between threads of same process is extremely fast.

Process Synchronization, Critical Section & Semaphores

Critical section criteria, Peterson's algorithm, counting semaphores, mutexes, and classical IPC problems.

The 3 Mandatory Criteria for Critical Section Solutions

  1. Mutual Exclusion: If process P_i is executing in its critical section, no other process can be executing in that critical section concurrently.
  2. Progress: If no process is executing in its critical section and some processes wish to enter, only those processes not in their remainder section can participate in deciding who enters next, and selection cannot be postponed indefinitely.
  3. Bounded Waiting: There must exist a bound (limit) on the number of times other processes are allowed to enter their critical sections after a process has made a request to enter and before that request is granted.
Counting vs Binary Semaphore

• Counting Semaphore: Takes any non-negative integer value; used to control access to a finite pool of identical resource instances (initialized to N).
• Binary Semaphore: Value is restricted to 0 and 1; used for mutual exclusion.
• Mutex vs Semaphore: A Mutex has thread ownership (only locker can unlock). Semaphores allow cross-thread signaling.

Classical Synchronization Problems

• Producer-Consumer: Uses 3 semaphores: mutex=1, empty=N, full=0.
• Readers-Writers: Multiple readers allowed simultaneously; exclusive access for writer. Uses wrt=1, mutex=1, readcount=0.
• Dining Philosophers: 5 philosophers, 5 chopsticks. Deadlock prevented by asymmetric pickup (odd left-first, even right-first).

4 Necessary Coffman Conditions for Deadlock

1. Mutual Exclusion: At least one resource must be held in non-shareable mode.
2. Hold and Wait: A process must be holding at least one resource and waiting to acquire additional resources held by others.
3. No Preemption: Resources cannot be preempted forcibly; they can only be released voluntarily by the holding process.
4. Circular Wait: A set {P0, P1, ..., Pn} exists such that P0 waits for P1, P1 waits for P2, and Pn waits for P0.
Banker's Algorithm Core Matrices
Available[m]: Number of available instances of each resource type.
Max[n, m]: Maximum demand of each process.
Allocation[n, m]: Resources currently allocated to each process.

TLB Effective Access Time (EMAT)
EMAT = H * (T_tlb + T_m) + (1 - H) * (T_tlb + 2 * T_m)
H = TLB Hit ratio (typically 90–98%).

⚡ Belady's Anomaly Definition

Belady's Anomaly is the phenomenon where increasing the number of physical page frames allocated to a process results in an INCREASE in the number of page faults for a given reference string. It occurs in FIFO page replacement (e.g., reference string: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 has 9 faults with 3 frames, but 10 faults with 4 frames!). Stack algorithms (LRU, Optimal) never suffer from Belady's anomaly.

File Systems, UNIX Inode Architecture & Disk Scheduling

FCFS, SSTF, SCAN (Elevator), C-SCAN, Inode block pointers, and file allocation methods.

UNIX Inode Structure

• Contains all file metadata (size, owner UID, GID, permissions, timestamps).
• 12 Direct Block Pointers: Point directly to first 12 data blocks (e.g., 12 * 4 KB = 48 KB).
• 1 Single Indirect Pointer: Points to a block containing 1024 data pointers.
• 1 Double Indirect Pointer: Points to a block containing 1024 single-indirect blocks.
• 1 Triple Indirect Pointer: Allows files to scale to terabytes.
• File Name is stored in directory entry, NOT inside the Inode!

Disk Scheduling Algorithms

• FCFS: First-Come-First-Served (fair, but high total head movement).
• SSTF: Shortest Seek Time First (minimizes seek distance; risks starvation).
• SCAN (Elevator): Head sweeps back and forth servicing requests to the edges.
• C-SCAN: Services in one direction only; returns immediately to start without servicing.
• LOOK / C-LOOK: Like SCAN/C-SCAN, but reverses at the last request instead of traveling all the way to disk boundary.
